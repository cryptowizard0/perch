## 2. 先要修的：别人在调 `perch hook claude-code`

好几家默认读 `~/.claude/settings.json` 的 hooks：

- **Cursor**（IDE 和 CLI）：Settings → Agents → Third-Party Imports，默认开。映射 `UserPromptSubmit`→`beforeSubmitPrompt`、`Stop`→`stop`、`SessionStart/End`、`PreToolUse/PostToolUse`；`Notification`、`PermissionRequest` 不支持；工具名 Bash→Shell。给 Claude 格式 hook 的 stdin 是哪种 schema 文档没说（未验证）。
- **Devin CLI / Devin Local**：`read_config_from.claude` 默认开。
- **VS Code**：`chat.useClaudeHooks` 默认关；Copilot CLI 只读仓库里的 `.claude/settings.json`。
- **Grok Build**：默认读 `~/.claude/settings.json` **和 `~/.cursor/hooks.json`**（`[compat.claude] hooks = false` / `[compat.cursor]` 可关；本机已关 Claude 的）。所以将来装了 Cursor hooks，Grok 也会调 `perch hook cursor`。
- **Zed 的 Claude Agent**：跑的是真 `claude` 二进制（argv[0] 是绝对路径，basename `claude`），本来就该算 Claude Code，不用拦。

后果：本机已装 Perch hooks 的用户在 Cursor 里用 agent，可能冒出一条来源是 claude-code、没有 pid（只能等 24 小时兜底）的会话，或者 hook.log 里出现解码失败。**每个适配器都要认出外来调用方并丢掉**，不只 `claude-code`：祖先链里没有本家进程就不报（Cursor IDE 没有会话进程，改认 `CURSOR_VERSION`）；Grok 调用时环境里有 `GROK_HOOK_EVENT`，Cursor 有 `CURSOR_VERSION`。

## 4. 共性改动（接第一个新 agent 时顺手做）

1. **进程识别不能只看 argv[0]。** Node 写的 agent（Gemini、Qwen、Auggie、Cursor CLI 可能也是）argv[0] 是 `node`，要再看 argv[1] 的 basename；npm 装的 `copilot` / `opencode` 会多一层 node 父进程（找最近的那个就行）。`AgentProcess` 要支持按 argv[1] 匹配。
2. **没有会话进程的宿主**（Cursor IDE、VS Code、Kilo / Cline 扩展）：pid 存活检测拿不到，只能靠 `sessionEnd` + 24 小时兜底。可能要给这类会话一个更短的空闲清理。
3. **决定 JSON 按 agent 分支。** `HookAdapter.decision(agent:answer:)` 已经按 agent 分，新增 Cursor 扁平格式、Copilot 顶层 `behavior`。
4. **插件型 agent**（OpenCode / Kilo / Amp / Pi）：插件只做转发，`spawn("perch", ["hook", "opencode"])` 把事件 JSON 喂进 stdin，状态映射仍在 Swift 的 `HookAdapter`，保持"一种语言"。插件文件由 `perch hooks install opencode` 写出。
5. **没有"等你"信号的 agent**（Cursor、agy）：Needs you 只能来自我们自己的阻塞 hook——hook 被调用时记成 waiting，返回 / 下一个事件时回 running。白名单外的命令照样秒回 `ask`。

## 5. Pi

`@earendil-works/pi-coding-agent` 1.1.0（2026-10-07），源码 `earendil-works/pi` main。

- 只有进程内 TS / JS 扩展（jiti 加载）：`export default function (pi) { pi.on("<event>", async (event, ctx) => …) }`。全局 `~/.pi/agent/extensions/*.ts`，无信任步骤；项目级 `.pi/extensions/` 要项目信任。改了要 `/reload` 或重启。
- **Pi 默认不问权限**（`docs/security.md`），所以没有"等你批准"，只做状态。扩展自己弹的框有 `ui_prompt_start` / `ui_prompt_end`，可当 Needs you。
- 映射：`input`（`text`）/ `before_agent_start` → running；`tool_execution_end` → running；`agent_settled {aborted}` 定结果（Pi 会在 `agent_end` 后自动重试 / 压缩，所以别在 `agent_end` 判）：`aborted` → idle，末条 assistant `stopReason:"error"` → failed（`errorMessage`），否则 done（末条文本）；`session_start` / `session_shutdown`（`quit` = 移除；`new` / `resume` / `fork` = 换 session id）。
- 会话 id：`ctx.sessionManager.getSessionId()`；cwd：`ctx.cwd`；会话文件 `~/.pi/agent/sessions/…/<ts>_<id>.jsonl`。
- 进程：npm 的 node 脚本，但启动时 `process.title = "pi"`，`ps` 里就是 `pi`（模拟验证）；环境里有 `PI_CODING_AGENT=true`。扩展 spawn 的 `perch` 父进程就是 pi。
- 只在 `ctx.mode === "tui"` 时上报，`pi -p` / json / rpc 模式也会加载扩展，不过滤会冒幽灵会话。
- OpenClaw 是聊天网关（像 Hermes gateway），和刘海的编码会话无关，不做。

## 6. 建议顺序

已定（2026-10-10，用户）：Cursor 的 IDE 会话和 CLI 一起接（共用 `~/.cursor/hooks.json`）；VS Code Copilot 的 Local harness 不接。顺序待用户确认，确认前不开工。
